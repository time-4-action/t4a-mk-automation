Overview

Customer Sync mirrors customers (Metakocka partners) one way — from T4A → CREAGLOBE. T4A is the single source of truth and is never written to. Customers that already exist in CREAGLOBE are updated to match T4A; customers that are missing are created.

⚠ No shared key. Unlike products (which share a code), partners have no business key shared between the two companies — the partner count_code and mk_id are per-company internal values (measured: 0 count_code overlap). Customers are therefore matched by tax number first, and by exact name as a fallback.
✔ Preview (Dry Run). Because a mismatch could create a duplicate customer, use Preview (Dry Run) to compute exactly what a run would create/update without writing anything to CREAGLOBE. The plan is recorded in the admin run history.

How Matching Works

  • Tax number (normalised: spaces stripped, upper-cased) — primary key, reliable for businesses.
  • Exact name (normalised: trimmed, lower-cased, whitespace collapsed) — fallback for private consumers with no tax number.
  • A T4A customer that matches an existing CREAGLOBE one → updated using CREAGLOBE's own mk_id.
  • A T4A customer that matches nothing → created in CREAGLOBE.

Contacts & Delivery Addresses

Contacts and delivery addresses are synced too, but their IDs differ per company, so they are matched by content so that repeat runs don't duplicate them:

  • Billing address (Račun) is reconciled by role — CREAGLOBE's existing billing address is updated in place, never duplicated.
  • Other delivery addresses are matched by type + street + post number + city; missing ones are added.
  • Contacts are matched by name + email + phone; missing ones are added and attached to CREAGLOBE's billing address.

Key Features

  • Strictly one-way (T4A → CREAGLOBE). T4A is never modified.
  • Configurable schedule (15 min, hourly, every 3 hours, daily) and day-of-week selection.
  • Run now, or preview with a dry run first.
  • Every run is recorded with per-customer error details in the admin run history.
